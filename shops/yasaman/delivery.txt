تسک هفتهٔ سوم: سوپرمارکت یاسمن با npm، Vite و TypeScript
سطح تحویل: قبولی، بخش اصلی ۱۰۰ نمره‌ای. بخش Bonus و چالش‌های اختیاری انجام نشده‌اند. نمرهٔ نهایی با آموزشگاه است.

اجرا
وارد پوشه‌ای شوید که package.json داخل آن است؛ در این نسخه shops/yasaman/ است.
اگر کد را مثل هفتهٔ دوم در shops/info-hiding/info-hiding/ قرار می‌دهید، تمام دستورهای npm را از همان پوشه اجرا کنید. فایل‌های قدیمی پوشهٔ بالاتر را جایگزین نکنید.
Node باید با ابزارهای نصب‌شده سازگار باشد: برای این نسخه Node 22.12 یا جدیدتر در شاخهٔ ۲۲، یا Node 24 پیشنهاد می‌شود. تست این پروژه با Node 22.14.0 انجام شده است.

npm ci
npm run dev

آدرسی که Vite چاپ می‌کند را باز کنید. Live Server و دابل‌کلیک روی HTML دیگر روش اجرای این پروژه نیستند.
در PowerShell اگر اجرای npm.ps1 مسدود شد، همین دستورها را با npm.cmd اجرا کنید؛ نیازی به تغییر تنظیمات امنیتی ویندوز نیست.

بررسی و خروجی نهایی
npm run check
npm run build
npm run preview

preview خروجی dist را اجرا می‌کند. برای تغییر کد از dev استفاده کنید. node_modules و dist را در Git ثبت نکنید.
فایل app.js قبلی حذف شده و فقط app.ts منبع اصلی است. هنگام انتقال نسخهٔ جدید روی نسخهٔ قدیمی، app.js قدیمی را هم حذف کنید.

API
vite.config.ts درخواست‌های /api را به https://gof.zzb.cx می‌فرستد. dev و preview هر دو همین proxy را دارند.
کد fetch همچنان ../../api/ را استفاده می‌کند؛ در ریشهٔ سرور Vite این آدرس به /api/ تبدیل می‌شود.
برای اجرای این نسخه به پوشهٔ API محلی نیاز نیست، ولی اینترنت و در دسترس بودن سایت آموزشگاه لازم است. پوشهٔ api محلی و مشترک تغییر نکرده است.
proxy تنظیمیِ dev و preview مربوط به سرورهای Vite است؛ برای میزبانی استاتیک dist باید میزبان مسیر /api را هم پشتیبانی کند.

اثر پکیج‌ها
packages.png پیام notyf، افکت confetti و تعداد یک در سبد خرید را هم‌زمان نشان می‌دهد.
افزودن فقط شمارندهٔ همین صفحه را زیاد می‌کند؛ بعد از Reload شمارنده صفر می‌شود. دکمهٔ کالای ناموجود disabled است و چیزی اضافه نمی‌کند.
متن toast ثابت است تا نام محصول دریافتی از API به HTML داخلی کتابخانه داده نشود. کارت‌ها مانند هفتهٔ دوم با createElement و textContent ساخته می‌شوند.

خروجی TypeScript قبل و بعد
check-before.txt خروجی واقعی اولین اجرای check پس از تبدیل app.js به app.ts و قبل از اصلاح نوع‌هاست؛ ۱۱ خطا ثبت شد.
چند خط نمونه:
app.ts(75,5): error TS18047: 'carousel' is possibly 'null'.
app.ts(78,9): error TS18047: 'statusMessage' is possibly 'null'.
app.ts(91,67): error TS2339: Property 'hidden' does not exist on type 'Element'.
check-after.txt خروجی بررسی نسخهٔ نهایی است و هیچ خطای TypeScript ندارد.

خطای جالب TypeScript
querySelector ممکن است null برگرداند؛ همچنین Element کلی، ویژگی hidden ندارد. برای controls نوع HTMLDivElement درخواست شد و برای نبود عنصر if گذاشته شد. برای کاروسل‌های section نوع HTMLElement استفاده شد. تابع‌ها برای نگه داشتن بررسی null در closure به شکل const و arrow نوشته شدند. خطا با ! یا as مخفی نشده است.
همچنین کاروسل‌های دارای نام دسترس‌پذیر از div عمومی به section تبدیل شدند تا هم HTML استاندارد و هم قانون prefer-native-element اعتبارسنج آکادمی رعایت شود. شمارهٔ تلفن خط تیرهٔ نشکن دارد.

تفاوت dependencies و devDependencies
notyf و canvas-confetti در dependencies هستند؛ کدشان برای استفادهٔ کاربر وارد خروجی مرورگر می‌شود.
TypeScript، Vite و @types/canvas-confetti در devDependencies هستند؛ ابزار ساخت، بررسی و نوع‌ها هستند و به‌عنوان ابزار در مرورگر اجرا نمی‌شوند.
اسکریپت build ابتدا tsc --noEmit را اجرا می‌کند؛ اگر خطای نوع وجود داشته باشد، && مانع اجرای vite build می‌شود.

package-lock.json و node_modules
فایل قفل نسخه‌های دقیق و وابستگی‌های تو در تو را ثبت می‌کند تا npm ci روی سیستم دیگر همان درخت نصب را بازسازی کند.
node_modules فایل‌های نصب‌شده و وابسته به سیستم را دارد، حجیم است و از روی فایل قفل دوباره ساخته می‌شود؛ نباید Commit شود.
dist خروجی تولیدشده است و در این تمرین نباید Commit شود.

تفاوت dev و preview
